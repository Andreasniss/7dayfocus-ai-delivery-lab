## Problem

The working project and its evidence remain private. The README explains the product boundary and links lifecycle artifacts, yet it does not give a new reviewer a concise explanation of the Anthropic method being demonstrated or its relationship to the more comprehensive AWS AI-DLC method. The website still describes a private release candidate and lacks a companion comparison article.

## Outcome

Publish one consistent, public-safe reference surface: a verified public repository, a README that explains the source method and local adaptation, a synchronized website case study, and a sourced article comparing Anthropic, AWS, and OpenAI approaches to AI-native software delivery.

## Constraints

- Preserve the existing local-only, synthetic-data, proposal-only product boundary.
- Do not claim Anthropic compliance, endorsement, internal-process equivalence, production readiness, or live-provider quality.
- Link official primary sources and distinguish their claims from this project's conventions.
- Make visibility public only after code, documentation, dependency, disclosure, review, and visual gates pass.
- Keep the demo and website claim surfaces synchronized.
